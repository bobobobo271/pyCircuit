# 原型验证记录

日期：2026-11-28。分支：`WSE_parallel`。

本轮先完成小网格原型，再验证 5×8、40 节点。原生模型在本次测试范围内保持了 coarse 的事件顺序与模型时间，真实调用了 GFSIM 并行执行器。当前多线程版本比同一实现的串行版本慢，尚未取得宿主执行加速。

## 构建与依赖

GFSIM 固定为 `cc833bf4003aac17f0177067e70ecaffaf0d54c3`，在新工作区从源码构建。编译器为 LLVM Clang 22.1.8，C++11，Release 使用 `-O3 -DNDEBUG`。运行环境为 macOS 26.5.2、ARM64，系统报告 10 个逻辑 CPU；线程未绑核。

coarse 对照使用原工作区已有的 `coarse-v11/build/coarse_runner`，每次实际重新运行，哈希写入验证回执。本轮未重建该旧二进制，也未把旧构建产物复制到新工作区。新旧执行时间不作性能比值比较。

## 正确性结果

条件固定为每源一个传输、全部从时刻 0 就绪、开放 Calendar、52 B 有效载荷和 64 B 线传/flit、零端点及固定开销。常规跳延迟为 1，单变量对照仅将其改成 3。

| 阶段 | 场景 | 结果 |
| --- | --- | --- |
| 最小原型 | 单跳、两跳、跳延迟、独立流、接收争用、共享链路、组播与本地目标、非目标尾支排空 | 8 个场景通过 |
| 40 节点 | 全节点成对双向交换、覆盖全部节点的树广播、共享链路、经过节点 33 的组播 | 4 个场景通过 |

每个场景执行单事件串行、批处理串行和 1/2/4/8 工作线程，共 72 次原生运行。完整事件、时间和字节统计一致；12 个场景均与实际 coarse 运行逐事件匹配。检查包含手算时刻、每条树边的 flit 数、每周期链路和共享接收端口占用。

具体例子：200 B 两跳完成于模型时刻 5；仅将每跳延迟改为 3 后完成于 9。两个源各向同一节点发送 52 B，接收按旧插入顺序发生在时刻 1、2，反转传输 ID 和输入列表也保持这个顺序。源 0 在本地完成写入后仍沿 `0→1→2` 转发的场景，写完成于 0，网络及源退休结束于 3。

独立审阅发现原测试错误地把最后写完成当成模型结束，已修正并加入上述尾支排空场景。复核确认问题闭环。

另外用 ThreadSanitizer（线程数据竞争检测器）构建 GFSIM 和原生模型，采用 `-fsanitize=thread -g -O1`，重新执行同一 72 次矩阵，通过且未报告数据竞争。Release 的两项 WSE CTest、GFSIM 延迟消费及并行子树两项针对性测试均通过。

Black 24.10.0 格式检查通过。Ruff 0.11.8 下载在四次尝试后超时，本轮未执行 Ruff；没有提交或更新远端 PR。

## 并行粒度与性能

以下为独占本任务测量阶段的结果；该阶段未同时执行构建或回归测试。每种负载、线程配置丢弃前 2 次，再测 7 次，轮换配置顺序。事件保存关闭，同一可执行文件、同一输入、同一模型参数，计时仅包含 Step 循环。每次样本重新创建进程和系统，线程在一次完整仿真内复用。构建时间、进程总墙钟及进程 CPU 时间另存原始记录。

| 负载 | 串行中位数 | 4 工作线程中位数 | 8 工作线程中位数 |
| --- | ---: | ---: | ---: |
| 40 节点成对交换，每源 520 B | 10.335 ms | 91.547 ms | 138.243 ms |
| 全网树广播，源 0、200 B、40 个目标 | 4.457 ms | 39.551 ms | 65.912 ms |
| 两个源共享链路，各 200 B | 0.499 ms | 4.511 ms | 6.063 ms |

成对交换的串行 7 次范围为 9.871–12.858 ms，4 线程为 90.035–103.071 ms。4 线程相对串行的加速比约 0.113，即耗时约为串行的 8.86 倍。全部 135 次运行（30 次预热、105 次正式采样）都检查了模型时间、流量和批次数一致。

事件统计说明了当前任务粒度：成对交换处理 1720 个事件，分成 1174 批，最大批宽为 40，但平均每批只有约 1.47 个事件；请求、执行、回复使其需要 3522 个 GFSIM 步。全网广播只有一个源，在当前同源串行规则下，514 个事件全部是单事件批次。

因此，原型已经证明不同源之间存在可同时执行的任务，但目前的批次划分没有形成足够大的持续并行工作量。每批需要多次队列交接和阶段同步，实测线程开销超过收益。尚未对同步、队列操作和状态复制分别做时间剖析，后续应先测这些占比，再实现分区内连续处理和更大的安全批次。增加虚构算术工作不纳入 WSE 性能结论。

这组结果用于判断当前实现的扩展性，不代表 WSE 硬件时间。模型时间和宿主运行秒数始终分开记录。

## 证据与后续范围

本地原始证据位于 `docs/gates/logs/wse-parallel-20261128/`：

- `benchmark/benchmark.json`：早期探索样本，曾与短回归重叠，保留但不用于上表。
- `candidate.json`：最终源文件与可执行文件身份、coarse 工作区保留检查。

构建期间默认系统 SDK 无法完成 ARM64 链接，改用工作区已有的 LLVM 和现代 SDK 后通过。一次原地重新链接后的可执行文件被系统以 SIGKILL 结束；保留失败记录及二进制，移开该输出后重新链接到新文件，随后完成全部最终验证。这里仅记录观察和恢复步骤，不把原因当作已证实的结论。

当前原型已达到“模型时间、争用顺序、串并行一致性，并扩展到 40 节点”的阶段目标。完整程序控制、容量及时隙功能仍按 README 列出的范围待接入；下一轮性能工作应先解决细粒度批次问题，再判断是否扩大模型功能。
