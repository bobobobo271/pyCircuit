# 显式配置与语义

## 共享通信功能配置

普通 Python 语义保留 40 节点 Calendar 基线和 48 节点白皮书两种拓扑。
当前 `WseMachine` 使用 5×8 的 40 节点空间，全部节点都可寻址。每节点逻辑
存储为 65536 字节，数据拍为 8 字节；通信轮次为 8 位，程序容量为 1024 条。
实际程序长度在启动时给出。

机器一次执行一个完整片段，每节点一个活跃接收上下文、2 个早到元数据槽和
56 个去重槽。这些是当前功能模型的显式资源。早到元数据行为由共享组件回归
保留；机器数据执行要求先建立远端接收，不提供早到载荷缓存。

源地址、目的地址、长度须满足 8 字节对齐和节点内完整范围约束。接收范围
错误或新增字节使计数超过容量时，保留此前账本并报告协议故障。新有效身份
超出去重容量时，终止模拟并报告模型容量不足；重复身份不重复写入或计数。
源自身副本由 self_copy 选择，独立于远端接收计数。

## AllGather 基线程序

32 个成员使用节点 0–31，排成 4×8。行阶段为四个八成员组，列阶段为八个
四成员组。每个节点输入 384 个 FP32（32 位浮点）元素，即 1536 字节。
行组收集后每节点持有 3072 个元素；列组收集后持有按源节点编号排列的
12288 个元素，即 49152 字节。元素按原始位模式复制，不进行浮点运算。

每阶段 32 个源，每源 8 个片段，共 256 个 COPY；两阶段共 512 个 COPY。
行片段为 192 字节，列片段为 1536 字节；每成员行阶段收到 56 个远端身份、
10752 字节，列阶段收到 24 个身份、36864 字节。程序还包含配置、轮次、
POST、WAIT、RETIRE 和 END 指令，指令总数与 COPY 数分开记录。

输入起址 0，行输出起址 4096，列输出起址 16384。这些地址、成员和分片数
由 AllGather 程序给出，换合法程序时不重新构建硬件。当前 PTO 适配验证受限
通信子集，不提供任意 PTO 算子的解释执行。

历史 Calendar fixture 按张量行分片，PTO 基线采用 rank-major 连续布局；
两者的几何与周期分别保存，不混为同一个数据执行测试。

## 专项时序投影

`models/pto_allgather/timing_profile.json` 保存显式参数、单位、来源及确定状态。
它与 `timing.py`、对应驱动构成独立的 analysis-only 行列时序投影；暂定 UB
服务带宽、首拍延迟、跨时钟域开销与时窗等参数继续标记 `pending`。

功能机器的串行执行周期、专项投影的 NoC（片上网络）周期和实际硬件测量应
分别记录。修改参数后，用独立分析与生成时序模型核对对应工作负载。
