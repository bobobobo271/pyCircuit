# WSE 粗粒度 NoC 仿真方案

日期：2026-11-26；2026-11-27 已授权实施。以下保留原方案，实际行为与验收以 README 和运行报告为准。

最新要求：分支改为 `deaigns/WSE_coarse`；旧机器源码只保留在 `designs/WSE_model` 分支，新分支仅保留粗粒度生成模型。用户另授权遇到预算耗尽时临时提高编译预算。

目标是在现有 `designs/wse_model` 内增加 `CoarseWseMachine`，仿照 SparseFA
的资源调度模型，用通信元信息、资源占用和完成事件模拟 WSE（晶圆级系统）的
NoC（片上网络）。调用者提供节点、路由、字节数和依赖，不提供设备字节地址或寄存器配置。

当前 `TimedWseMachine` 已将模型时间与模拟器内部执行步数分开，但仍有真实节点

## 2. 建模范围

推荐第一版采用“无载荷、按 flit 元信息推进的资源模型”。flit 是链路传输的基本单位；
这里只保留它所属的传输、序号和有效字节数。去掉数据通路并不要求去掉网络拓扑。

| 对象 | 当前时序模型 | 粗粒度版本 |
| --- | --- | --- |
| 节点与链路 | 40 节点 5×8 网格、方向链路 | 保留，首版仍用同一拓扑 |
| 路由 | 80 位路由、逐跳转发 | 外部使用路由编号或转发树；适配器解码旧路由 |
| 组播 | 分支分别争用出链路 | 保留公共路径只传一次、分叉后分别服务 |
| 数据 | 实际源内存、包缓冲与目的写入 | 传输 ID、逻辑数据块 ID、字节计数、完成标记 |
| 地址 | 源/目的地址、对齐、写掩码、内存镜像 | 从新接口和模型数据通路移除 |
| 端点存储 | 实际整包读取与写回 | 读写带宽、首拍延迟、端口占用及容量额度 |
| 接收状态 | POST、epoch、去重、地址范围等详细账本 | 逻辑通信组、预期传输、已完成字节与依赖 |
| Calendar | 链路时隙许可、配置账本、加载地址 | 保留时隙许可；输入为链路与时隙的许可表 |
| 完成 | 真实写入完成后账本提交 | 接收端服务完成后发布逻辑完成标记 |
| 计算 | 通信模型尚未接入数值计算 | 首版专注通信；预留任务释放时间即可 |

Calendar 在这里指按时间窗限制哪些源可以使用某条链路的调度规则。
默认兼容 profile 保留现有时隙；另设全开放 profile 用于单独分析网络争用。
两者结果分别标记，避免把取消 Calendar 等待误报成实现加速。

新模型仍需持久计数器、队列和资源状态；这些由 pyCircuit 编译成内部存储。
用户无需描述被模拟设备的寄存器编号、位域或地址映射。

首版覆盖有效、显式同步的通信程序。原详细模型继续负责载荷、地址及接收协议验证。
新模型验证传输身份、字节量、顺序和资源限制。旧的详细时序规范保持原义，新增独立
coarse 规范，避免把“真实写入”悄悄改成“计数完成”。

## 3. 输入与执行过程

新的 `Transfer` 至少包含：

```text
id, source_node, route_id, nbytes, logical_block_id,
release_time, dependency_group, completion_group
```

路由配置提供转发边与接收节点；一个目的节点可以同时接收并继续转发。
同一逻辑数据块可以拆成多条传输，每条传输 ID 唯一。分片身份是逻辑信息，
不要求提供内存偏移。`WaitGroup` 等待指定通信组的接收端服务全部结束。
兼容旧程序的 `Barrier` 则全局排空等待队列、活动包和转发事件，增加原配置的
`alignment + arm` 时间，并将此刻设为新的 Calendar 时间原点；两者不能混用。

宿主 Python 负责拓扑、路由校验、工作负载与配置装载；pyCircuit 模型负责运行时
仲裁、事件时间、接收进度与完成。宿主不预先算好完成时刻再交给模型播放。
沿用 source compile → link → verified final → C++/Verilog 的编译路径。

一次传输按以下过程执行：

1. 依赖完成且达到释放时间后，进入源节点有限队列。
2. 获得源读端口，按字节数和端点参数安排读完成事件；此事件使通信数据逻辑可用。
3. 将字节量转换为 flit 数。只调度元信息，不逐字节读取包缓冲。
4. 各 flit 逐跳请求方向链路。链路可用且 Calendar 放行时占用资源，经过单跳延迟到达下一节点。
5. 分叉生成独立出链路请求；共享树干的流量只记一次。首跳各分支接受后才能注入下一 flit，沿用当前约束。
6. 每个目的跨所有入方向合计每周期最多接收一个 flit；接收仲裁独立于链路和写端口。该目的收到整包后申请写端口；写服务结束才更新完成字节与逻辑数据块可用状态。
7. 全部目标完成且转发事件排空后释放活动传输。依赖它的通信才可继续。

首版保留现有每源 1 个活动包、8 个等待描述符、单 flit 注入额度和有限事件队列。
这些是兼容基线的模型容量，不标作硅片参数。继续采用当前转发事件抽象，不增加
物理路由器 FIFO（先进先出缓冲）或信用返回流水；端点许可延迟仍是抽象接收停顿。
源等待队列满时暂停发包，队列释放后恢复；这类临时占用采用回压。
接收容量不足、单包超过配置容量或事件堆溢出则显式报错，沿用兼容基线的有限资源边界。
发包前向各目标预留本包字节额度；写服务完成后从预留额度转入已完成额度，
直到逻辑接收组退休才释放该组容量。传输 ID 仅完成一次，报错不得产生完成标记。
去掉实际内存后，端点容量仍以额度计数，不能变成无限容量。

同一时刻的仲裁沿用稳定插入顺序。对照用例保持传输顺序、事件优先关系、发包边界
及本地 self-copy 服务一致。`self-copy` 是源节点保留本地副本，仍占本地写服务，
但不增加链路字节。无关传输的元信息处理只增加宿主执行步，不增加 NoC 模型时间。

旧程序适配器先支持现有 AllGather 生成器：保留分片、路由、发送顺序、WAIT 和
BARRIER，将 POST/RETIRE 转成逻辑组生命周期。PTO（已有算子编程与编译链）入口
继续复用现有工作负载生成结果。任意旧程序的地址别名不能直接丢弃：只有能从现有
阶段屏障证明读写依赖的用例才接入，其他用例须显式补充逻辑依赖。

## 4. 时间与流量的定义

沿用当前兼容参数：64 B 线传 flit、52 B 有效载荷、每方向每 NoC 周期一个 flit。
52 B 与端点首拍、时隙等暂定参数继续保留 `pending` 来源标记。

对 `S` 个有效字节，`F = ceil(S / 52)`。每条经过的方向链路记 `64 × F` 个线传
字节；每个接收目标记 `S` 个有效字节。末 flit 的填充也占链路服务时间。
链路占用间隔与传播延迟分开：单跳延迟增加不自动降低每周期的注入吞吐。

链路候选服务时刻取 flit 到达、链路空闲和 Calendar 放行条件共同满足的最早时刻。
服务后更新链路占用，再安排下游事件。端点服务沿用当前首拍加后续拍的公式，
不能把首拍预算与完整 `S / 带宽` 重复计费。

一个可手算的例子：关闭端点与固定开销，Calendar 全开放，单跳延迟为 1 周期，
发送 200 B，路径为 0→1→2，共 4 个 flit。第一 flit 在 t=0 发出、t=2 到达，
最后一个在 t=3 发出、t=5 到达。因此无争用尾部到达时间为 `H + F - 1 = 5`。
中继收到一个 flit 就能继续发送，无需等整包收齐。若简化为每跳整包存储转发，
会改变这种流水关系，因此首版不采用该近似。

如后续仍有性能瓶颈，再研究将一串无争用 flit 合并为区间事件；合并必须在争用、
Calendar 边界和端点停顿处拆开。更粗的分块大小属于模型选项，需单独量化误差。
本方案不承诺尚未测量的宿主加速倍数。

## 6. 验收与控制变量

以下均为计划，尚未执行 coarse 仿真。

| 用例 | 固定条件与唯一变化 | 独立检查 |
| --- | --- | --- |
| 单跳、多跳 | 200 B、开放 Calendar、端点/固定开销为零、1 flit/周期；仅改跳数 | 尾部到达 `H+F-1`，每跳流量与目标字节正确 |
| 并发与争用 | 两条等长流、相同释放时间/端点参数；选等跳数且目的不同的路径，仅改变是否共享方向链路 | 无共享链路时并行；共享链路服务不重叠，总负载守恒 |
| 组播 | 一个源、三个目标且含节点 33；固定传输与路由树 | 公共边只传一份，各目标完成一次，本地副本不走网络 |
| Calendar | 同一传输和参数，仅关闭某方向的一个时隙 | 该时隙无服务，后续开放窗口继续；其他无关链路照常推进 |
| 汇聚端点 | 两条不同入链路同时到达同一目标、相同释放和端点参数 | 链路可并行，目标合计仍至多接收 1 flit/周期 |
| 阶段屏障 | 固定两阶段传输、时隙和端点参数 | 全局排空后计入 alignment+arm，第二阶段按新的 Calendar 原点放行 |
| 端点限制 | 同一流量，仅延迟一个目的接收许可 | 该目的完成及其依赖推迟，无关传输继续 |
| 容量边界 | 固定配置；先用可容纳的连续包填满源等待队列，再单独用一个超过接收容量的包 | 前者等待后恢复且不丢包；后者拒绝且不产生完成，检查预留/完成/释放守恒 |
| AllGather | 同一 5×8 网络上的 32 个参与者，保持现有行/列分组、分片、路由和屏障 | 每目标获得全部逻辑源块；列阶段依赖已完成行数据 |
| 宿主性能 | 同上游 SDK、同编译选项、单 worker、同输入/profile、同 trace 设置；两模型分别新构建 | 分开报告构建、加载、执行、输出时间及峰值内存 |

先用独立手算小用例检查模型，再与同配置 `TimedWseMachine` 比较有共同语义的
传输事件、接收完成和总模型时间。若出现差异，定位到路由、仲裁、端点或控制开销，
不能把 detailed 输出写进 coarse 模型充当答案。兼容的正向场景以共同事件一致为目标；
新逻辑接口的内部微步骤无需一致。详细模型的载荷逐字节验证单独报告。

性能对照先用小型场景确认语义，再测 32 参与者 AllGather。每种实现先预热一次，
正式重复三次、交替运行，保留每次原始耗时、报告中位数和范围。模型时间是 NoC
周期，宿主执行时间是秒，二者分列；只在相同 trace 模式下计算加速比。

结果至少保存配置与工作负载哈希、编译器/源码版本、总模型周期、逐传输完成时间、
每链路线传字节及占用、每目标有效字节、各类等待、实际事件轨迹与宿主耗时。
各类等待可能同时发生，未经互斥归因不得直接求和成总时间。
