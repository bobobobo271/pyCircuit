# WSE 功能模型的运行时程序接口

本接口用于把通信程序加载到同一套 WSE 功能模型，不是新增真实 WSE 指令集。
硬件 profile 显式指定 40 节点的 5×8 拓扑、每节点 65536 字节存储、8 字节
数据拍、8 位轮次、一个在途片段，每节点早到槽 2 个、去重身份槽 56 个。
程序清单必须与这份已编译配置完全一致；修改容量需要重新构建硬件。程序决定参与者、路由、
地址、长度、期望接收量和操作顺序。

## 指令编码

一条指令为 16 个小端无符号 32 位字段，共 64 字节。程序为这些记录的连续
拼接，实际条数由加载器在 start 时给出；容量 1024 条是本次显式硬件配置。
地址为节点内字节地址。长度正且为 8 的整倍，起址 8 字节对齐，完整访问范围
必须落在节点存储内；加法先扩宽检查，再转换为存储地址。

| 字段序号 | 字段 | 语义 |
| --- | --- | --- |
| 0 | kind | 1 INSTALL、2 NEXT_EPOCH、3 POST、4 COPY、5 WAIT、6 RETIRE、7 END |
| 1 | node | 配置、轮次、接收操作的节点，范围 0–39 |
| 2 | opcode | 通信操作码；0、7 保留 |
| 3 | epoch | 接收与发送所用轮次，范围 1–255，须与对应节点计数器一致 |
| 4 | seq | 片段身份中的序号，范围 0–65535 |
| 5 | source | COPY 的源节点，范围 0–39 |
| 6 | src | 源节点内地址 |
| 7 | dst | 接收范围起址或 COPY 在各落点的目的地址 |
| 8 | nbytes | COPY 的完整片段字节数 |
| 9 | capacity | POST 的接收地址范围大小 |
| 10 | expected | POST 的远端有效接收字节数，自身副本不计入 |
| 11 | compiled_expected | 程序编译器从布局与组推导的预期量，POST 检查二者一致 |
| 12–14 | route_lo、route_mid、route_hi | COPY 的 80 位 P/L 路由，最低字在前，最高字段仅低 16 位有效 |
| 15 | flags | bit 0 为 self_copy，其余位保留为 0 |

不使用的字段由程序生成器填 0。运行时检查有关字段的完整原始值，不能通过
窄位截断把非法输入变成合法节点、地址或操作码。

## 操作语义

INSTALL 使用共享配置准入实现，只在相关状态排空后安装 opcode。
NEXT_EPOCH 使用共享轮次实现，在排空条件下推进所选节点的计数。
POST 使用共享接收账本建立上下文。WAIT 等待该上下文完成，RETIRE 释放它并
清空本轮身份记录。END 要求无在途片段且全部接收上下文已退役。

COPY 对程序提供的原始路由逐跳执行 ForwardHop。其源节点必须 P=1，遍历必须覆盖路由中的全部 P 节点；远端
L=1 的节点构成落点。源自身是否复制由 self_copy 明确决定，不计远端字节。
仅源节点 P=1 且 self_copy=1 可表达本地复制，无需源接收上下文。
本地源、目的区间须不重叠，或者完全同址。

数据执行 profile 要求先 POST、后 COPY，一次只执行一个完整片段。
所有远端目标的配置、轮次、范围、去重与容量都通过预检后才开始写。
每个写入拍再次检查本片段全部待写远端落点的许可；该集合在预检后固定至
COPY 完成，排除重复身份与源自身，不随逐目标完成而缩小。
缺少许可时保持 PC、目标和拍内偏移，
不提交该拍写入。重复身份跳过整段写与计数；正常目标的末拍写、
身份插入和计数更新在同一事务提交。先前已成功写入的拍不承诺整段回滚。
旧接收接口的早到元数据语义由同一账本核心保留，本数据 profile 不引入早到
载荷缓存、多个在途片段、物理链路时序或归约语义。

## 宿主与状态接口

`HostRequest` 按声明顺序包含 kind:u3、node:u6、address:u32、data:u64、
program_count:u16、landing_permit:bits40。
kind=0 空闲，1 写节点内存，2 写程序内存，3 启动，4 读节点内存，5 观察节点。
加载只允许 idle；读回允许 idle、done 和锁存的普通 fault。程序以 8 字节拍
加载，start 的 program_count 取程序实际指令条数。非法请求锁存普通 fault；kind 6、7 未定义。

`MachineResult` 按声明顺序包含 data:u64、pc:u16、stage:u5、selected_node:u6、
offset:u32、counted:u32、active:bool、complete:bool、pending:u8、epoch:u8、fault:bool、
fault_code:u8、done:bool、read_bytes:u64、write_bytes:u64。
读回与账户观察的节点由 host.node 选择；selected_node 是硬件当前处理的节点，
与 host.node 分开。PC 是指令索引，offset 是片段内拍偏移。
epoch 是所观察账户保留的轮次。
流量来自成功执行的
源读取与目的写入，不能从 AllGather 阶段或组大小猜算。

普通协议或范围错误在写入前锁存 fault，停止 PC，并保留诊断读回。
身份资源耗尽保持现有容量断言的终止语义；终止后的内存快照不可据此宣称可读。

## 宿主文件

通用 C++ 驱动读取四类文件，所有工作负载共用同一个模拟器：

- `program.bin`：64 字节指令记录。
- `image.bin`：重复的 `{node:u32,address:u32,nbytes:u32}` 小端记录，紧跟该段
  原始字节，用于启动前初始化；地址与长度按 8 字节对齐。
- `readback.bin`：重复的 `{node:u32,address:u32,nbytes:u32}` 小端记录，描述
  完成后需要读出的范围；不携带预期数据。
- `output.bin`：按 readback 范围顺序拼接的实际读回字节。

文件名只是调用约定，驱动接收显式路径。独立测试从原始 image 与算法定义
构造期望，不把答案写入程序或硬件。

该裸记录格式固定为接口版本 1，由构建回执与程序清单声明。记录本身不含
版本头；加载器和驱动须使用相同接口版本，不能宣称从裸字节自动识别版本。
